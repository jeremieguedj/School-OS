# Start or resume an operation

This is a bounded orientation procedure for a capable agent, including one that
has never used this household's School-OS before. It does not require previous
chat history or a local instance mirror.

1. **Find the parent's intended entry point.** Use their Drive pointer to the
   readable START-HERE document. For first setup follow [setup](setup.md) instead.
   Read the instance ID, official material revision, logical areas and how to
   locate their directories. A URL is an access aid: check internal instance and
   role identities. An ambiguous duplicate is unresolved; do not choose the first
   folder with a matching display name.
2. **Select the requested operation.** Use the parent's current request or their
   already authorized job instruction. Choose setup, ingestion, a knowledge query,
   task synchronization, daily update, a manual brief or a compatible extension.
   Do not reinterpret a question as permission to send messages or import mail.
3. **Read only required instructions and configuration.** Follow the selected
   recipe and its dependencies, selected source/household settings and shared
   tool mappings. Canonical [data](../contracts/data.md) and
   [identity](../contracts/identity.md) contracts govern meanings; credentials
   remain in this agent's authorized connection system.
4. **Check available means for this operation.** Use [tool adapters](tool-adapters.md)
   to map School-OS meanings onto tools this agent can actually access. Reuse the
   shared mapping through the current connector; do not assume another agent's
   connector capabilities or permissions are present. Report a required missing
   operation. Code execution is required, but using a particular helper on every
   step is not. The actual [small helper](../helpers/source_metadata.py) is optional
   where its documented mechanical operation applies.
5. **Read relevant canonical state and coverage in bounded pages.** Use
   [storage](storage.md) and the selected operation's directories. Ingestion checks
   unfinished source windows and known not-ingested mail. A query checks relevant
   source/index freshness. A general question does not drain unrelated work first.
6. **Proceed under existing authority.** Read saved state and perform only the
   selected authorized operation. If a relevant dependency is incomplete, resolve
   it within authorization or disclose the limitation under the query/manual-brief
   rules. Follow [continuation](continuation.md) for saved unfinished discovery.
   General repair after an interrupted canonical write is outside this MVP.
7. **Leave truthful results.** Save and read back affected canonical pages and
   required directory/index updates using the contract. Report verified results,
   incomplete work and unsupported capabilities distinctly. Do not advance a
   completeness claim merely because an agent session or resource batch ended.

Only one agent operates on an instance's data at a time. Users and their agents
coordinate their own schedules. This procedure installs no locks, leases, job
registry, hidden background process or new automatic job.
