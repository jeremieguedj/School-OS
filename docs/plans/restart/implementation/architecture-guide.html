Current direction

Use capable agents; keep School-OS focused

School-OS provides

  • Canonical source-linked knowledge, tasks, source indexes and coverage on Drive.
  • Explicit recipes, identity rules, completion requirements and small Python standard-library helpers.
  • Guidance for manageable source reads, verified saving and temporary-copy cleanup.
  • D5’s approved corrections, recurring actions and parent task-state behavior.

The executing agent manages

  • Its resources, practical batch sizes, task continuity and runtime recovery.
  • Following the recipe through the complete intended ingestion.
  • Checking uncertain effects using its available authorized tools.
  • Its own scheduled jobs and adapter selection, with no concurrent use of the same instance data.

No School-OS batch controller. The old 25-processing/100-listing/8 MiB application caps are withdrawn. D1’s limits on individual JSON and directory pages still apply; they do not cap a whole run.

The product’s broader principles remain intact. D2 interrupted canonical-write repair, the separate records/save framework, D7 central register/scheduler management and D8 packaged lifecycle are explicit MVP deferrals. This guide does not claim they have been delivered.

One logical run

Complete ingestion comes before the daily brief

1 · Establish scope
Read the recipe, source configuration and relevant saved coverage. The proposed finite daily cutoff still needs approval.
↓
2 · Agent manages work
The agent follows discovery pages and processes email/reply/attachment content in batches it chooses for its resources.
↓
3 · Verify completion
Check complete relevant discovery, content processing and saved knowledge/coverage. A finished batch is not a finished daily task.
↓
4 · Compose and deliver
Only after ingestion is verified complete, create the daily brief. The agent uses its available means to validate uncertain external actions.

Fictional example: 40 pending appearances can be handled in five batches of eight, two of twenty or another suitable pattern. At 25 processed, the agent is still working. Appearance 31 might correct Friday’s deadline to Thursday.

If a real access/content/runtime blocker prevents completion, report the incomplete task. Do not substitute an ordinary partial daily brief. A separate knowledge question may still receive verified facts with an explicit limitation.

Written illustration only. No run, simulation, connector probe or test was executed. Agent continuity is a design assumption; School-OS supplies no general interrupted-write repair engine.

Approval ledger at a glance

What is approved, deferred and open

D1 · Approved

Multiple bounded JSON pages and paged directories on Drive, with a readable bootstrap and separate system, instance and extensions areas. The 64 KiB page and 100-entry directory-page defaults are not per-run email limits or whole-history caps.

Approved storage design →

D2 · Recovery outside MVP

School-OS interrupted canonical-write repair remains deferred. The separate records/ordinary-save framework is also outside MVP. Agent saving and verification remain required. The separately approved query-coverage rule permits useful verified answers with honest gaps.

Framework deferral →

D3 · Minimal Python direction approved

Start with small standard-library routines for subject normalization, extracted address parts and UTF-8 size. Recipes name the script; the agent and authorized tools do the rest. The helpers are authored but unexecuted. No SDK or fixed provider set is selected. It does not require a personal computer, coding CLI or persistent local service.

D4 · Revised execution direction approved

One logical run must complete all relevant unread/unprocessed mail. The executing agent manages batching and runtime resources with School-OS guidance. The finite scope/cutoff and remaining original-Date/discovery details still need decisions.

D5 · Approved in full

Source-linked claims and corrections; finite/conditional/recurring tasks; the 14-day recurrence projection fallback; separate parent plans/completion; and three-way task synchronization. Agent operations preserve these approved meanings; no separate record/save framework is required.

D6 · Verification and timing approved

The agent assesses its available means to verify uncertain effects. Complete intended ingestion is required before daily brief composition. Content selection, task-app freshness handling and optional audio retention/order remain open; no central effect engine is selected.

D7 · Outside MVP

No central tools/jobs register or schedule-control subsystem. Users and agents arrange jobs, read recipes and select adapters, assuming nonconcurrent operation. The MVP does not promise a register-backed inventory of jobs or their managing schedulers.

D8 · Outside MVP

Defer package installation, version/compatibility management, upgrades and migrations. Keep D1 separation and reusable instructions/code distinct from household data. First-use agent instructions follow approved D1; repository history and privacy remain protected.
