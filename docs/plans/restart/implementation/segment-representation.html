Q10 · decided 16 September 2026

Keep one 64 KiB page maximum

School-OS will keep complete canonical records on one bounded JSON page. The proposed linked-piece format was rejected.

Current decision. Every encoded UTF-8 JSON page remains at or below 64 KiB. Collections of ordinary records continue across existing pages. If one complete record cannot fit, retention blocks with the observed size and private source evidence. It is never truncated or silently reshaped.

Why start here

School-OS stores processed Knowledge per claim and Tasks per independently completable action. It does not copy raw emails or long attachments into Drive. The fictional examples are small and only illustrate record shapes; no real-instance overflow distribution shows that the current maximum is too small.

One limit is simpler for fresh agents. It avoids segment IDs, cross-file reconstruction, extra verification, copy-on-change chains, unreachable old pieces, and additional Drive reads and writes.

What a larger page would change

  • Possible benefit: fewer page reads for a scan, or room for a real whole-record outlier.
  • Possible cost: more bytes for each whole-page rewrite and readback, plus more irrelevant records if a connector sends the complete page to the model.
  • Route dependency: an agent may download and filter JSON in temporary code storage, while another connector may inject a whole file or retrieve indexed chunks. Drive bytes are not model-visible tokens.

Public limits do not settle this. Gemini's warning concerns content that exceeds its context window, not a 256 KiB School-OS page (Google). Claude says aggregate Drive files added to a chat must fit its context, without publishing per-read connector granularity (Anthropic). ChatGPT Work usage varies with model, environment, settings, task complexity, tools and frequency, while actual charges depend on the workspace agreement and credits (OpenAI). No upload or context limit guarantees connector behavior.

Easy increase if evidence calls for it

If an actual source-supported whole record exceeds 64 KiB, or the authorized evaluation shows a material I/O or query benefit, change the one maximum in the shared installed data contract to 128 or 256 KiB. No new configuration field or registry is needed. Existing pages, stable record IDs, locators, catalogues and references remain valid, so no eager migration is required. Older agents must read the updated contract, and the larger size still requires route-specific evidence.

Evaluation already prepared

After complete implementation publication, the requested trial evaluation will use the prepared marked noncanonical 64/128/256 pages built in the same instance from the same already-ingested records and ask the same source-grounded questions. It will not reread the source or create another instance. Measure exact page and record bytes, observable I/O, model-visible tokens when exposed, query completeness, irrelevant context and latency. If no larger page is actually exercised, report 128/256 as unexercised.

The original “lost in the middle” study supports measuring distractors and evidence position, but its older model results do not prove current managed agents degrade at these sizes (Liu et al.).
